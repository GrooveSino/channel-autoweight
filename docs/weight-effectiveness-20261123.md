# 权重有效性复核与直接评分映射候选（2026-11-23）

> 状态：诊断与候选设计；未实现、未部署，运行仍为固定 v5.01。本提交只同步既有脱敏观察和本说明，不修改决策程序或任何配置。

## 已证实的问题

- 当前不是正常性能差异持续择优分流：rank会产生不同目标，但Settle将未达渠道故障门槛的降档恢复为旧值；旧值均在硬上限20，导致性能差异无法反映到权重。
- 纯函数离线重放58轮、116份双profile决策：评分与最终目标116/116重现；464个渠道轮次中356条策略目标低于20，最终仍全20。这证明收口机制抹平差异，不证明现有分数已无偏识别各模型优劣。
- 故障门为真实样本至少30、去集中错误至少3且比例至少3%；不是监测原始错误率。GPT配对偏慢另有例外，复核样本中未出现slow判定；另一profile未开启该例外。
- 20是全局硬上限和rank顶档，不是全局保底。无须突破20，也能靠降低相对差渠的权重增加好渠命中概率。
- 现有源代码证据：`decide/settle.go:59–93`、`decide/strategy.go:194–228`、`decide/decide.go:257–263`、`decide/pairslow.go`。仅改cut_needs_fault开关仍无法绕开Settle中无故障恢复旧值的独立分支；只换评分/策略也不够。

## 用户提出的方向：每轮可靠评分直接映射目标

把“本轮应分多少流量”与“上一轮加减多少”分开：

1. 每轮从真实请求构造可比性能分数q；同模型、输出长度、必要的输入长度/缓存/推理负荷分层，保留样本量与不确定性。不直接用跨模型端到端均速给渠道排名。
2. 在同一可竞争集合中把分数映射为目标权重，高分保持上限，低分随相对表现变化。例如候选 `target_i = clamp(round(max_weight × (q_i/q_best)^gamma), exploration_floor, operator_cap_i)`，再明确操作员cap绝对优先。这只是公式示意，非已选定参数或现行规则。
3. 示例完全合成：q=[.90,.75,.60]、上限20、gamma=1得到目标[20,17,13]。这不是从旧权重累计奖励/扣分，也不是固定±2就是评分模型。
4. 通过分数平滑、置信度、滞回/持续证据抑制抖动。是否保留目标变化速率限制，应作为独立执行保护评估；不能让保护永远否决无type5故障的性能差异，也不能把没错误当成所有渠道回20的理由。
5. 保留真正的故障快速避让、恢复和操作员上限；“性能相对落后”和“渠道故障”是不同分支。无新样本时标未知并采用事先确定的探索/保持策略，不能把0样本当好表现。

当前适配器把同一渠道全部授权abilities权重绑定为同一值。因此初版若仍保持此约束，必须说明跨模型汇总使用的固定参照需求权重与覆盖范围，不能随着渠道自己流量构成变化任意换评分分母。若改成每模型独立权重，属于另一个需要批准的范围变化。

## 证明机制有效，而非只证明程序没报错

- 同group/model/priority/endpoint且满足路由条件的集合里，验证高可靠分数对应更大随机命中概率；单候选没有分流空间，亲和/指定渠道与重试流量另列。
- 不假定所有路由都用同一个公式：缓存路径可能按weight归一，非缓存路径可能加平滑常数；必须以实际部署版本、开关及完整候选集为准。
- 对合成[20,17,13]，纯weight随机池概率为[40%,34%,26%]；不是生产实测。所有权重均20时再怎么排序也不改变同池随机命中概率。
- 无泄漏顺序回放至少6/12/24/48h，覆盖模型占比变动、夜间薄样本、单会话错误集中、性能变差但无错误、故障及恢复、操作员cap。检查模型分层首字/端到端分位数、错误/有效空回复、差渠暴露和波动。
- 过去“与人工最终权重一致”及verified_noop只能证明运行/复现，不是用户体验提升指标。请求级反事实也有选择偏差，离线重加权不是因果效果证明。
